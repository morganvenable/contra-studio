# Archived shared-swing study

The app uses Standard presentation only. The experimental controls were removed
at the user’s request; future animation comparisons are separate clips. The
internal study code and tests are retained for offline research. The following
records the former bounded comparison and its evidence, not an app option.

The study is a geometry-preserving browser port of reciprocal model 1309cde7
(reference SHA-256
`1309cde755d668e5ad28eae6569df85951a3b069e94196edb31ac71413bd78af`).
The earlier 272ea12a model is not used.

## Bounded comparison

Only the complete canonical Dance fingerprints recorded in the deeply frozen
reviewed binding registry qualify. All Dance properties participate in SHA-256;
titles, catalog IDs and URLs alone never admit a dance. Exactly six couples and
these absolute count windows are supported:

- Butter: 6–17 and 50–65
- Monday (ContraDB 57): 18–33
- Emma's Emergency (ContraDB 2418): 38–49
- Another Safe Production (ContraDB 2604): 22–33

Windows are never repeated with modulo arithmetic. Outside a reviewed source,
window, count or renderer, standard presentation remains visible and the control
explains the reason. Edited sources fail closed. The compiled runtime binding is enabled only for the independently qualified
1309 port. It is not a user-controlled or imported setting.

## Pose and contact ownership

The source frame, source contacts, dancer identity, root position/heading and
musical transport remain authoritative and unchanged. Existing visible avatars
retain their labels, selection, picking and styling. A separate controller
reuses their standard post-anchor poses, then changes only their articulation.

Physical contact dots are derived from the posed geometry. Traveling hands
suppress their old source contact dots, even when source choreography describes
a full-strength hold. A fully attached pair produces two directed blade-palm
contacts and one deduplicated leading-hand contact. Acquisition progress is a
route parameter, not a force or contact strength. Unrelated hand contacts remain.

Private reference avatars and deterministic acceleration caches are bounded to
1,024 frames, 512 foot plants and 128 arm intervals. They are cleared on mode,
source binding, dance and set-size changes or disposal. The controller never
disposes visible avatars. Leaving the study restores prior head orientation,
hand dimensions and candidate-only diagnostics before ordinary articulation.
Forward/reverse seeks and cache eviction must reproduce the same posed matrices.

## Known limits

- New same-couple hey supporting-forearm/leading-hand overlap: 42.82 mm
- Fast continuous acquisition: up to 4.20 m per count in the measured balance
  window; production is about 0.76 m per count there
- Inherited fractional pose jumps and smaller torso/arm overlaps remain
- Stylized kinematic weight-sharing cue, not a force simulation, global
  continuity guarantee or continuous collision proof
- Visual-direction feedback and actual browser/GPU verification remain pending

The optional study is not approval to change the standard renderer.

## Reproducible checks

No dependency installation is needed:

- `node --experimental-strip-types --test src/swing-study.test.ts`
- `node --experimental-strip-types --test src/scene-presentation.test.ts`
- `node_modules/.bin/tsc --noEmit`

The commands above are self-contained in the app snapshot. The checked-in
`qa/swing-study-port-results.json` is separate frozen-reference audit evidence.
Its audit script, `qa/check-swing-study-port.mjs`, additionally requires the
archived sibling reference tree at
`../qa/body/shared-swing-v2/frozen-source/`; that script is not a standalone app
regression. With the matching reference archive present, run
`node --experimental-strip-types qa/check-swing-study-port.mjs` from the app.

The external comparison records the port's own source hashes, separately from
the reference algorithm hash. It compares 818 CPU-posed avatar samples across
all five reviewed windows and both footwork modes, including the precise former
fractional-jump bracket. Headless DOM/unit/CPU geometry checks do not establish
WebGL or GPU behavior.
