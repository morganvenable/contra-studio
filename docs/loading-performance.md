# Ready-library loading

The Ready library opens exact, locally bundled interpretation archives. A visible
Preparing message appears before synchronous validation. Loading still depends
on the device and source complexity; the interface does not promise instant opens.

## Exact program reuse

The public choreography compiler keeps at most six successful programs and 2 MiB
of exact input keys in an LRU cache. The complete dance, source snapshot, reviewed
choices, capability object and couple count participate. Optional property
presence, negative zero, property order and shared-reference shape are preserved.
Malformed prototypes, hidden or symbol fields, accessors and cycles cannot
obtain a cache hit. Inputs are captured directly from data descriptors; no later
keying or compilation reads the original. Browser JavaScript cannot generally
identify proxies, so a proxy may provide plain captured data, but cannot change
already captured values or make a later-installed getter run. Failed compilation is never cached. Oversized keys
compile normally without entering the cache. The cache exists only in the current
application build and is not persisted.

Every call receives a separate frozen public facade. Source and identity metadata
are owned by that recipient, and every sampler result is copied. Nested finite
rounds, trajectories and readonly relation-map protocols are also owned; their
iterators and callback map arguments cannot expose private cached state. A changed
source or withdrawn interpretation/capability still takes the normal admission
path. Archive validation itself has not been bypassed.

The earlier diagonal-only JSON-key cache was removed. Its path certificate code
now reuses private polynomial derivatives/products and exact binomial constants.
Arithmetic order, interval refinement, clock precision and all motion outputs are
unchanged. There is no rounded coordinate key or approximate path reuse.

## Reproduction

Run the installed TypeScript checker, then the focused tests:

```
./node_modules/.bin/tsc --noEmit
node --experimental-strip-types --test src/owned-program-cache.test.ts src/choreography-cache.test.ts src/ownership.test.ts
node --experimental-strip-types scripts/benchmark-ready-latency.mjs
```

The benchmark also accepts an immutable application directory for comparison.
Run each build in a fresh process and alternate builds to reduce load bias. It
separates import/validation, final compilation, camera bounds and 1,000 sampled
frames. Actual-main offline Open, Play and repeat checks are additionally required
before release; these microbenchmarks alone do not establish UI responsiveness.
